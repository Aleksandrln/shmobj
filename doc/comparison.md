# Сравнение с альтернативами

## `multiprocessing.shared_memory`

- `SharedMemory` — именованный кусок памяти, массив байт. Структуру в него кладут сериализованной, обычно через
  `pickle`, и каждый читатель делает `pickle.loads` и держит полную копию: память та же, что без общей памяти, плюс
  время на распаковку.
- `ShareableList` читается без копии, но это плоский список фиксированной длины из `int`, `float`, `bool`, `str`,
  `bytes` и `None`: ни вложенных списков, ни словарей; завершающие `\0` строк теряются.
- `SharedMemoryManager` — не хранилище: его процесс запоминает имена созданных `SharedMemory` и `ShareableList` и
  удаляет их при `shutdown()`.

`shmobj` кладёт в общую память вложенные `dict`/`list` целиком и читает их без распаковки.

## `multiprocessing.Manager().dict()`

Это `SyncManager`: данные — обычный `dict` в процессе-сервере, у клиентов только прокси. Каждое `d[key]` — запрос к
серверу через сокет, ключ и значение идут через `pickle`. Вложенный `dict` из `d[key]` приходит копией, его
изменение в сервер не попадёт. Сервер — один процесс со своим GIL на всех клиентов.

`shmobj` читает общую память в своём процессе, без запросов и сериализации. Плата — данные только для чтения: новый
набор публикуется новым снимком.

## `fork` и copy-on-write

Дочерний процесс после `fork` получает память родителя без копирования, пока страницы не меняются. Для
Python-объектов это не работает:

- **Чтение — тоже запись.** Обращение к объекту меняет его счётчик ссылок в заголовке объекта, и страница копируется
  в память ребёнка. Один проход по миллиону записей копирует около **340 МБ в каждый** дочерний процесс — даже после
  `gc.freeze()`.
- **Данные фиксируются в момент `fork`.** Обновление в родителе дети не увидят.
- **Нужен общий родитель с загруженными данными.** Независимые процессы и сервисы так данные не разделят.
- **`fork` есть не везде.** На Windows его нет, на macOS `multiprocessing` по умолчанию использует `spawn`, на Linux
  с Python 3.14 — `forkserver`: данные в каждом процессе загружаются заново.

Страницы сегмента `shmobj` никто не меняет: счётчики ссылок есть только у прокси и прочитанных значений.
