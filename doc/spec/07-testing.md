# 07. Тестирование и приёмка

## 1. Уровни тестов

| Уровень | Инструмент | Что проверяется |
|---|---|---|
| Ядро | `cargo test`, `proptest` | Кодирование слотов (границы SMALLINT, SHORTSTR 0–7 байт, UTF-8), хэш ключей против векторов из эталона, поиск в LINEAR/SORTED32 с принудительными коллизиями `h32`, круговое преобразование |
| Golden | `cargo test` + pytest | Каждый `golden/*.bin` проходит `validate`, и `loads(...).materialize() == golden/cases.py[имя]` |
| Fuzz | `cargo-fuzz` | `validate(data)` и случайный доступ без `validate` (цель выбирает путь по байтам входа): ни одной паники, таймаута или превышения памяти. Корпус: `golden/*.bin` |
| Сверка с эталоном | pytest + hypothesis | Для случайных структур (стратегия из `reference/test_ref.py`) выполняется: `ref.load(shmobj.dumps(v)) == v`, `shmobj.loads(ref.build(v)).materialize() == v`, а `validate` в Rust и эталоне даёт одинаковый результат на одних байтах |
| Семантика API | pytest | Всё из `02-api.md`: эквивалентность ключей `1/1.0/True`, `TypeError` и `KeyError` при поиске, `get_many` с `default` и без, срезы с шагом и отрицательные, `==` с `dict`/`list`/`tuple`, `repr`, отказ `hash` и `pickle`, порядок итерации |
| Межпроцессные | pytest, `spawn` и `fork` | Создатель → N читателей; читатель видит те же значения; `attach` в 3.11–3.12 не вызывает предупреждений `resource_tracker` и не удаляет сегмент при выходе читателя |
| Жизненный цикл | pytest | Доступ после `close()` → `SegmentClosedError`; `attach` после `unlink` → `FileNotFoundError`; `close` идемпотентен; `loads` поверх `mmap` удерживает экспорт |
| Утечки | pytest | 10⁶ операций чтения (`[]`, `get_many`, итераторы, ошибки `KeyError`): стабильные `sys.getrefcount` у сегмента и `len(gc.get_objects())`, прирост RSS < 1 МБ |
| Ошибки сборки | pytest | Неподдерживаемые типы и ключи с путём в сообщении, циклы, подклассы `dict`/`list`, строки с суррогатами |

## 2. Обязательные граничные случаи

- Пустые `dict`/`list` на всех уровнях вложенности и как корень; скаляр как корень.
- `int`: 2⁵⁹−1, −2⁵⁹, 2⁵⁹, ±(2⁶³−1), −2⁶³, 2⁶⁴, ±2²⁰⁰.
- `float`: 0.0, −0.0, ±inf, NaN как значение (сохраняется, ключом быть не может), субнормальные.
- `str`: пустая, 7 и 8 байт UTF-8, многобайтные символы на границе 7 байт, эмодзи, `\0` внутри и в конце.
- `bytes` с `\0` в конце (ошибка `ShareableList` не должна повториться).
- Словарь на 8 и 9 ключей (граница LINEAR/SORTED32); 10⁶ ключей.
- Списки на границах ширин: 255/256, −128/−129, 2³²−1/2³², `[True, 1]` (не типизируется).
- Тысячи словарей с одинаковыми ключами (одна KEYTABLE), а также с теми же ключами в другом порядке (другая KEYTABLE).

## 3. Повреждённые данные

Для каждого `golden/*.bin`: все однобайтовые изменения после заголовка, затем случайные
изменения 1–4 байт (≥ 10⁵ вариантов). Сборка идёт без контрольной суммы, чтобы проверялся
сам разбор. Допустимые исходы — корректное значение или `FormatError` /
`UnicodeDecodeError`. Паника, `SystemError`, segfault или зависание — дефект.

## 4. Бенчмарки

`benches/` (criterion) для ядра и `tests/bench_*.py` (pytest-benchmark) для Python.
Каждый Python-бенчмарк запускается парой: `shmobj` и та же операция на `dict`/`list` в
том же цикле. Результаты сохраняются в CI как артефакт.

## 5. Критерии приёмки v1

Эталонный набор:
```python
data = {f"user{i}": {"id": i, "name": f"name{i}", "score": i * 1.5,
                     "tags": ["a", "bb", i], "ok": True, "x": None} for i in range(10_000)}
```
Дополнительный набор: `{"users": [ ... те же 10 000 записей ... ]}`.

| Метрика | Цель |
|---|---|
| Размер сегмента / размер Python-объектов (`tracemalloc` на `deepcopy`) | ≤ 45% (эталон даёт 41%) |
| Размер относительно эталона | ±5% |
| `fd[k]`, словарь ≤ 8 ключей, ключ `str` | ≤ 3× `dict` |
| `fd[k]`, словарь 10 000 ключей | ≤ 3× `dict` |
| `fl[i]` | ≤ 3× `list` |
| `fd.get_many(keys)`, 1000 ключей, в пересчёте на ключ | ≤ 2× `[d[k] for k in keys]` |
| `for v in fd.iter_values()` | ≤ 2.5× `for v in d.values()` |
| `materialize()` | ≤ 2× `pickle.loads` того же объекта |
| `dumps(data)` | ≤ 3× `pickle.dumps(data)` |
| `attach(name)` | ≤ 50 мкс, не зависит от размера |
| RSS читателя после `attach` и одного доступа к `root["user42"]["name"]` | прирост ≤ 1 МБ при сегменте 100 МБ |

Плюс выполнены требования F1–F13 и N1–N9 из `01-requirements.md`, CI зелёный на всех
платформах N2, а 1 час fuzz без падений.
