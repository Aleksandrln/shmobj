# 03. Формат RO v1 (нормативный)

Исполняемая трактовка: `reference/shmobj_ref.py`. Порядок байт — little-endian везде.
Выравнивание: каждый узел начинается со смещения, кратного 8. Заполнение — нулями.
Смещение — число байт от начала сегмента.

## 1. Заголовок (64 байта, смещение 0)

| Смещение | Тип | Поле | Значение в RO v1 |
|---|---|---|---|
| 0 | `[u8;4]` | `magic` | `b"SHMO"` |
| 4 | `u16` | `format_version` | `1` |
| 6 | `u8` | `kind` | `0` = RO; `1` = RW (зарезервировано) |
| 7 | `u8` | `hash_algo` | `1` = xxh3_64, seed 0 |
| 8 | `u32` | `header_size` | `64` |
| 12 | `u32` | `flags` | бит 0 — `CHECKSUM` (поле `checksum` действительно); остальные биты = 0 |
| 16 | `u64` | `data_size` | полный размер данных, включая заголовок; ≤ размера буфера |
| 24 | `u64` | `root` | слот корневого значения |
| 32 | `u64` | `checksum` | xxh3_64 байт `[64, data_size)` или 0 |
| 40 | `[u8;24]` | резерв | нули; в RW здесь будут поля синхронизации и аллокатора |

Читатель обязан отклонить сегмент (`FormatError`), если неверны `magic`,
`format_version`, `hash_algo` или `header_size`, если `kind ≠ 0`, если `data_size`
выходит за буфер или в `flags` выставлены неизвестные биты.
`checksum` проверяется только по запросу (`verify=True`, `validate`).

## 2. Слот (u64)

`tag = slot & 0xF`, `payload = slot >> 4` (60 бит).

| tag | Имя | payload |
|---|---|---|
| 0 | NONE | 0 |
| 1 | FALSE | 0 |
| 2 | TRUE | 0 |
| 3 | SMALLINT | знаковое 60-битное: значение = `(slot as i64) >> 4` (арифметический сдвиг); диапазон [−2⁵⁹, 2⁵⁹−1] |
| 4 | INT64 | смещение узла INT64 |
| 5 | BIGINT | смещение узла BIGINT |
| 6 | FLOAT | смещение узла FLOAT |
| 7 | STR | смещение узла STR |
| 8 | BYTES | смещение узла BYTES |
| 9 | LIST | смещение узла LIST |
| 10 | DICT | смещение узла DICT |
| 11 | SHORTSTR | биты 0–3: длина `n` в байтах (0…7); биты 4–59: UTF-8 байты, байт `i` в битах `4+8i…11+8i`. Неиспользуемые биты = 0 |
| 12–15 | — | зарезервировано под RW; в RO недопустимо |

Для тегов-ссылок (4–10) смещение должно быть ≥ 64, кратно 8, а узел целиком лежит в `[64, data_size)`.

Выбор кодировки при сборке (нормативно, влияет на размер):
- `int`: SMALLINT, если помещается; иначе INT64, если помещается в i64; иначе BIGINT;
- `str`: SHORTSTR, если UTF-8 ≤ 7 байт; иначе STR.

## 3. Узлы скаляров (без заголовка, тип известен из тега слота)

| Узел | Раскладка |
|---|---|
| INT64 | `i64` |
| FLOAT | `f64` (IEEE 754, биты как есть, включая −0.0, inf) |
| BIGINT | `u32 nbytes`, `u32 0`, `nbytes` байт: минимальное дополнение до двух, LE |
| STR | `u32 byte_len`, `u32 char_count` (число кодовых точек), `byte_len` байт UTF-8 |
| BYTES | `u64 len`, `len` байт |

`char_count` позволяет создать `str` без повторного прохода. Если
`byte_len == char_count`, строка ASCII и копируется напрямую (быстрый путь).
Строки с суррогатами не принимаются при сборке.

## 4. Заголовок контейнера (8 байт)

| Смещение | Тип | Поле |
|---|---|---|
| 0 | `u8` | `node_type`: 1 = LIST, 2 = DICT, 3 = KEYTABLE; 4–127 резерв; 128–255 резерв под RW |
| 1 | `u8` | `subtype` |
| 2 | `u16` | `flags` = 0 |
| 4 | `u32` | `len` — число элементов |

## 5. LIST

`header(node_type=1, subtype, len)` и сразу за ним `len` элементов, с заполнением до 8 байт.

| subtype | Элемент | Размер | Чтение |
|---|---|---|---|
| 0 SLOTS | слот | 8 | по тегу |
| 1 I8 / 2 U8 | `i8` / `u8` | 1 | `int` |
| 3 I16 / 4 U16 | `i16` / `u16` | 2 | `int` |
| 5 I32 / 6 U32 | `i32` / `u32` | 4 | `int` |
| 7 I64 | `i64` | 8 | `int` |
| 8 F64 | `f64` | 8 | `float` |
| 9 BOOL | `u8` (0/1) | 1 | `bool` |

Правило сборки: если `len ≥ 2` и все элементы одного точного типа, то для `bool`
выбирается BOOL, для `float` — F64, для `int` — первая подходящая ширина в порядке
U8, I8, U16, I16, U32, I32, I64. Иначе SLOTS. Читатель обязан понимать любой
подтип при любом `len`.

## 6. KEYTABLE

`header(node_type=3, subtype, len)`, затем `keys[len]` (слоты), затем индекс, если `subtype = 1`.

| subtype | Индекс | Поиск |
|---|---|---|
| 0 LINEAR | нет | перебор `keys` по порядку |
| 1 SORTED32 | `index[len]` u64 = `(h32 << 32) \| entry`, по возрастанию | lower_bound по `h32`, затем перебор записей с тем же `h32` и сравнение ключей |

- `h32 = key_hash64(key) >> 32`, `entry` — позиция ключа в `keys`.
- Правило сборки: LINEAR, если `len ≤ 8`, иначе SORTED32. Читатель следует `subtype`,
  а не порогу.
- Слоты ключей допустимы только с тегами NONE, FALSE, TRUE, SMALLINT, INT64, BIGINT,
  FLOAT, STR, BYTES, SHORTSTR. Ключ не может быть NaN, и внутри таблицы ключи попарно не равны
  (по семантике Python `==`).
- Слот ключа ссылается на смещение меньше смещения своей KEYTABLE (пост-порядок, §9).
  Ключ-контейнер, NaN или повтор ключа — `FormatError` в `validate`.
- Порядок `keys` — порядок вставки исходного `dict`.
- Сборщик переиспользует одну KEYTABLE для всех словарей с одинаковой
  последовательностью ключей, где сравнение идёт по паре (точный тип, значение).

## 7. DICT

`header(node_type=2, subtype=0, len)`, затем `u64 keytable_offset`, затем `values[len]` (слоты).
`len` DICT равен `len` его KEYTABLE. Ключ `i` соответствует значению `i`.

## 8. Хэш ключа

`key_hash64(k) = xxh3_64(type_byte ‖ payload)`, seed 0:

| Ключ | type_byte | payload |
|---|---|---|
| `None` | `0x00` | пусто |
| `int`, `bool`, `float` с целым значением | `0x01` | минимальное дополнение до двух, LE: `v.to_bytes((v.bit_length()+8)//8, "little", signed=True)` |
| `float` с дробной частью или ±inf | `0x02` | 8 байт f64 LE |
| `str` | `0x03` | UTF-8 |
| `bytes` | `0x04` | сами байты |

Так `1`, `1.0` и `True` получают один хэш и находятся одинаково. Правило совпадает с
семантикой `dict`. Значение `-0.0` целое (0) и хэшируется как `0`.

## 9. Инварианты

1. **Пост-порядок:** каждая ссылка (слот-ссылка, `keytable_offset`) указывает на
   смещение строго меньше смещения узла, который её содержит. Для `root` ограничение
   одно: ссылка < `data_size`. Отсюда следует, что циклов нет и проверку можно сделать одним проходом.
2. Узлы могут разделяться: на один узел ссылается несколько слотов (дедупликация).
3. Все неиспользуемые и заполняющие байты нулевые. `validate` может это не
   проверять, но сборщик обязан так писать.
4. Сборка детерминирована: один и тот же вход и одни и те же параметры дают одни и те
   же байты. Совпадение байт с эталоном желательно, но не обязательно: обязательна
   взаимная читаемость и равенство значений.

## 10. Пределы

`len` контейнера ≤ 2³²−1. `byte_len` строки ≤ 2³²−1. `nbytes` BIGINT ≤ 2³²−1.
Смещение < 2⁶⁰.

## 11. Совместимость версий

- Новые подтипы, теги и типы узлов в RO требуют увеличения `format_version`.
- Читатель v1 отклоняет сегменты с другой версией.
- Поля резерва заголовка в v1 должны быть нулевыми.
