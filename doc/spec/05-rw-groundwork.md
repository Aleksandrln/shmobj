# 05. Задел под RW

RW — отдельный тип структур (`SharedDict`, `SharedList`) в сегментах с `kind = 1`.
RO и RW не смешиваются в одном сегменте. Переход между ними — явная операция:
`freeze(rw) -> bytes` (RO) и `thaw(ro) -> RW`.

Почему два типа, а не один: RO выигрывает в размере за счёт плотной упаковки
(таблицы без пустых слотов, типизированные массивы, общие таблицы ключей, ссылки
только назад). RW требует запаса места, аллокатора и синхронизации. Один формат на
оба случая проиграл бы в обоих.

## 1. Что общее и уже зафиксировано в v1

| Элемент | Где | Правило для v1 |
|---|---|---|
| Заголовок с `kind` | `format/header.rs` | Разбор заголовка возвращает `kind`; RO-читатель отклоняет `kind ≠ 0` сообщением «сегмент RW, нужна RW-версия». Ветвление по `kind` — одно место, а не проверки по коду |
| Резерв заголовка 40..63 | там же | В RO = 0. В RW планируется: `seqlock: u64` (40), `alloc_cursor: u64` (48), `free_lists: u64` (56) |
| Слот, теги 0–11 | `format/slot.rs` | Кодирование и декодирование скаляров — общий код. RW использует те же скалярные теги и узлы |
| Теги 12–15 | — | Зарезервированы: 12 = RW_LIST, 13 = RW_DICT, 14–15 = резерв. В RO-читателе тег 12–15 даёт `FormatError` |
| `node_type` 128–255 | — | Зарезервированы под узлы RW |
| Узлы скаляров | `format/scalar.rs` | Общие. В RW неизменяемы: запись нового значения = новый узел и замена слота |
| `key_hash64` | `format/hash.rs` | Общий; RW-хэш-таблица использует его же |
| Python ABC | `shmobj/__init__.py` | RO: `Mapping`/`Sequence`. RW: `MutableMapping`/`MutableSequence`. Общая база `shmobj.abc` появится вместе с RW |
| Имена API | `02-api.md` §8 | Зарезервированы, в v1 не определяются |

## 2. Правила кода v1, чтобы RW добавился без переделок

1. `format/` не зависит от `ro/`. Всё, что RO-специфично (KEYTABLE, типизированные
   списки, пост-порядок), лежит только в `ro/`.
2. Декодер скаляров принимает `&[u8]` и слот и не знает, RO это или RW.
3. `PySegment` знает `kind`; прокси получают декодер через сегмент, а не напрямую
   через функции `ro::`.
4. В Python-слое `create`/`attach` выбирают класс по `kind` из заголовка. В v1 при
   `kind = 1` они вызывают `FormatError` с понятным текстом.
5. Смещения в RO храним как есть (не делим на 8), чтобы слот-ссылка была одинаковой в обоих форматах.

## 3. Набросок RW (не реализуется, ориентир)

- Память: сегмент открывается в Rust по имени (`memmap2` поверх `/dev/shm/<name>`
  на Linux, `windows-sys` для named mapping на Windows). Рост — цепочка сегментов
  или заранее зарезервированный sparse-сегмент.
- RW_DICT: компактная хэш-таблица как у CPython (`indices` + `entries`) с запасом слотов.
- RW_LIST: массив слотов с ёмкостью и удвоением.
- Аллокатор: free-lists по классам размеров.
- Синхронизация: один писатель (межпроцессная блокировка на атомике в заголовке),
  читатели без блокировок через seqlock (`generation` до и после чтения).
- Освобождение: отложенное (epoch), потому что читатели могут держать старые смещения.
- Ориентир трудоёмкости: +1–1.5 месяца после v1.
