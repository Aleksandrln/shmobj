# 08. Этапы и трудоёмкость

Оценки рассчитаны на одного разработчика, знакомого с Rust; PyO3 можно осваивать по
ходу. Если Rust незнаком, добавьте 2–4 недели.

| # | Этап | Результат | Оценка |
|---|---|---|---|
| 0 | Каркас | Workspace, maturin, `skeleton/` разложен, CI: fmt, clippy, `cargo test`, pytest эталона, сборка wheel на трёх ОС | 2–3 дня |
| 1 | Ядро: чтение | `format/*`, `ro/reader`, `list`, `dict`, `validate`; golden читаются; fuzz-цели запущены | 4–6 дней |
| 2 | Привязки: чтение | `PySegment` (PyBuffer + closed), `FrozenDict`, `FrozenList`, срезы, представления, `get_many`, `iter_values`, `iter_items`, `materialize`, `==`, исключения; `loads`/`validate` | 5–7 дней |
| 3 | Сборка | `ro/writer` + `build.rs`: дедупликация, KEYTABLE, типизированные списки, пути в ошибках, циклы; сверка с эталоном через hypothesis в обе стороны | 4–6 дней |
| 4 | Жизненный цикл | `create`/`attach`/`close`/`unlink`, `resource_tracker` 3.11–3.12, `track=False` 3.13+, Windows; межпроцессные тесты | 2–3 дня |
| 5 | Производительность | Быстрые пути `str`/`int`, интерполяционный поиск, `PySequence_Fast` в `get_many`; бенчмарки и достижение целей `07-testing.md` §5; тесты утечек | 3–5 дней |
| 6 | Выпуск | README пакета, docstrings, `.pyi`, wheel в PyPI или во внутренний индекс | 1–2 дня |
| | **Итого v1 (RO)** | | **≈ 4–6 недель** |

Объём кода: примерно 2500–3500 строк Rust и 300–500 строк Python, без учёта тестов.

Точки контроля:
- после этапа 1 формат зафиксирован: все изменения формата — только через `03-format.md` и эталон;
- после этапа 3 обе реализации взаимно читаемы;
- после этапа 5 проверяется соответствие критериям приёмки.

После v1 (вне этого ТЗ):
- v1.1 — `pickle` прокси как (имя сегмента, смещение) с переподключением в дочернем процессе; buffer protocol у типизированных `FrozenList` (zero-copy в numpy); двухпроходная сборка прямо в `SharedMemory`.
- v2 — RW (`05-rw-groundwork.md`), ≈ +1–1.5 месяца.
