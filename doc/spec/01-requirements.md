# 01. Требования

## 1. Цель

Снизить потребление памяти при работе нескольких процессов с одними и теми же
вложенными структурами `dict`/`list`/скаляров. Сейчас каждый процесс держит свою копию
Python-объектов. Нужна одна копия в общей памяти в компактном формате, с доступом
через привычный интерфейс `Mapping`/`Sequence` и без десериализации всей структуры.

## 2. Границы v1

Входит в v1:
- RO-структуры: собираются один раз из Python-объекта и дальше не меняются;
- доступ на чтение из любого числа процессов без блокировок;
- пакетные методы `get_many(...)` и `iter_values()` у `FrozenDict` и `FrozenList`;
- работа поверх `multiprocessing.shared_memory.SharedMemory`, а также поверх любого
  буфера: `bytes`, `mmap` файла;
- полная проверка корректности сегмента (`validate`).
- канал снимков между процессами без следов в ОС после падения сторон (`shmobj.channel`, Linux и Windows; `02-api.md` §6).

Не входит в v1:
- изменение данных (это RW, отдельный тип, см. `05-rw-groundwork.md`);
- типы кроме перечисленных в §3: `set`, `tuple` как отдельный тип, `datetime`,
  `Decimal`, numpy, пользовательские классы;
- ключи-кортежи;
- PyPy и прочие реализации кроме CPython;
- обязательная поддержка free-threaded сборок (3.13t+); см. §5.

## 3. Поддерживаемые данные

| Python-тип | Хранение | Что возвращается при чтении |
|---|---|---|
| `None`, `bool` | встроено в слот | тот же тип |
| `int` | встроено (60 бит), int64 или bigint любой длины | `int` |
| `float` | узел f64 | `float` |
| `str` | ≤ 7 байт UTF-8 встроено, иначе узел | `str` |
| `bytes`, `bytearray`, `memoryview` | узел | `bytes` |
| `list`, `tuple` | узел LIST | `FrozenList` |
| `dict` (точный тип) | узел DICT + KEYTABLE | `FrozenDict` |

- Ключи `dict`: `None`, `bool`, `int`, `float` (кроме NaN), `str`, `bytes`.
  Эквивалентность ключей та же, что у `dict`: `1 == 1.0 == True`.
- Подклассы `dict`/`list`/`str`/`int` не принимаются (`TypeError`). Это нужно, чтобы
  поведение было предсказуемым и не терялись переопределённые методы.
- Если структура циклическая, сборка завершается `ValueError`.
- Ограничения: до 2³²−1 элементов в контейнере, строка до 4 ГиБ, сегмент до 2⁶⁰ байт.

## 4. Функциональные требования

| ID | Требование |
|---|---|
| F1 | `dumps(obj)` → `bytes` сегмента; `create(obj, name=None)` → `Segment` в новой `SharedMemory` |
| F2 | `attach(name)` подключается к существующему сегменту за O(1): читается только заголовок |
| F3 | `loads(buf)` → корневое значение поверх любого объекта с buffer protocol, без копирования |
| F4 | `FrozenDict` реализует `collections.abc.Mapping`, сохраняет порядок вставки исходного `dict`, поиск по ключу в среднем O(log n) для n > 8 и O(n) с n ≤ 8 |
| F5 | `FrozenList` реализует `collections.abc.Sequence`, индекс O(1); срез возвращает `FrozenList`-представление без копирования |
| F6 | `get_many(keys, default=...)` у `FrozenDict` и `get_many(indices, default=...)` у `FrozenList`: возвращают `list` значений за один вызов в Rust |
| F7 | `iter_values()` у обоих типов, `iter_items()` у `FrozenDict`: итераторы, реализованные в Rust, без Python-генераторов |
| F8 | `materialize()` у обоих типов: глубокое преобразование в `dict`/`list` |
| F9 | `validate(buf)`: полная проверка формата; при любом повреждении — `FormatError`, без паники, без UB и без зависаний |
| F10 | Чтение повреждённого сегмента без `validate` даёт `FormatError` при обращении к повреждённому месту, но никогда не приводит к панике, UB или чтению за пределами буфера |
| F11 | `Segment.close()` и `unlink()`; доступ через прокси после `close()` даёт `SegmentClosedError` |
| F12 | Сегменты, созданные эталоном (`reference/`), читаются Rust-реализацией, и наоборот. Все `golden/*.bin` читаются и совпадают с `golden/cases.py` |
| F13 | При подключении в 3.11–3.12 `resource_tracker` не должен удалять чужой сегмент при выходе процесса |

## 5. Нефункциональные требования

| ID | Требование |
|---|---|
| N1 | CPython ≥ 3.11; один wheel `abi3-py311` на все версии |
| N2 | Платформы: Linux x86_64 и aarch64 (manylinux), Windows x86_64, macOS arm64 |
| N3 | Размер: на эталонном наборе (`07-testing.md` §5) не более 45% от размера Python-объектов; расхождение с эталоном по размеру не более ±5% |
| N4 | Скорость: целевые значения в `07-testing.md` §5, относительно `dict` в том же цикле |
| N5 | Память процесса-читателя: прирост RSS пропорционален только затронутым страницам сегмента; прокси не кэшируют данные |
| N6 | Ядро формата (`shmobj-core`) без `unsafe` (`#![forbid(unsafe_code)]`); `unsafe` допускается только в слое привязок, каждое место с комментарием-обоснованием |
| N7 | Нет утечек ссылок: 10⁶ операций чтения не увеличивают число объектов и RSS |
| N8 | Free-threaded (3.13t+): в v1 не обязательно, но классы объявляются `frozen` и `Send + Sync`, чтобы поддержку можно было добавить без смены API |
| N9 | Документация: docstring у каждого публичного объекта, `.pyi` с типами, раздел в README про жизненный цикл сегмента |
